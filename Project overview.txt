# EXPLAINABLE PREDICTIVE MAINTENANCE MODEL - PROJECT OVERVIEW

## PROJECT DESCRIPTION

The Explainable Predictive Maintenance Model is a cutting-edge software system designed for industrial equipment monitoring and failure prediction. This comprehensive solution combines machine learning with explainable AI techniques to help maintenance teams make data-driven decisions. The system is enhanced with a complete IoT sensor network featuring 16 industrial sensors across 4 production lines, providing real-time visualization and monitoring capabilities.

## PURPOSE AND IMPORTANCE

This project addresses the critical need for predictive maintenance in industrial settings. Traditional reactive maintenance approaches are costly and inefficient, while scheduled maintenance often results in unnecessary downtime. This system provides:
- Proactive failure prediction to prevent unexpected equipment breakdowns
- Actionable insights through explainable AI models
- Real-time monitoring of industrial equipment health
- Cost reduction through optimized maintenance scheduling
- Improved operational efficiency and equipment lifespan

## CORE COMPONENTS

### 1. IoT SENSOR NETWORK (16 Industrial Sensors)
The system features a complete industrial IoT sensor network distributed across 4 production lines:

**Production Line A - Turbofan Engines (6 sensors):**
- Core Temperature Sensor
- Fan Vibration Monitor
- Compressor Pressure Gauge
- Turbine RPM Sensor
- Exhaust Temperature Probe
- Bearing Vibration Sensor

**Production Line B - Hydraulic Systems (3 sensors):**
- Hydraulic Pump Temperature
- Hydraulic Pressure Sensor
- Flow Rate Meter

**Production Line C - Electric Motors (3 sensors):**
- Motor Current Sensor
- Motor Voltage Monitor
- Motor Torque Sensor

**Quality Control & Cooling Systems (4 sensors):**
- Spindle Temperature
- Spindle Vibration
- Coolant Temperature
- Coolant Flow Meter

### 2. ARTIFICIAL INTELLIGENCE MODELS

**RUL Prediction (XGBoost Model):**
- Estimates Remaining Useful Life of equipment
- Provides time-to-failure predictions
- Offers confidence scoring for reliability assessment

**Failure Risk Classification (LightGBM Model):**
- Classifies equipment into risk categories (Low, Medium, High)
- Provides probability distributions for decision-making
- Enables prioritization of maintenance activities

**Anomaly Detection (Isolation Forest):**
- Identifies unusual patterns in sensor data
- Detects early signs of equipment degradation
- Flags potential issues before they become critical

### 3. EXPLAINABLE AI (XAI) FEATURES

**SHAP (SHapley Additive exPlanations):**
- Provides global feature importance analysis
- Explains model decisions at the system level
- Helps understand which sensors contribute most to predictions

**LIME (Local Interpretable Model-agnostic Explanations):**
- Offers local explanations for individual predictions
- Provides insight into specific decision factors
- Enables detailed analysis of critical equipment states

### 4. BACKEND ARCHITECTURE (Python/Flask)

**Core Components:**
- Flask REST API for handling HTTP requests
- Model Manager for loading and managing ML models
- Sensor Manager for IoT network simulation and control
- API Endpoints for all system functionalities
- Configuration management and logging systems

**API Endpoints:**
- Prediction API (/api/v1/prediction/*): RUL and failure risk predictions
- Explainability API (/api/v1/explainability/*): SHAP and LIME explanations
- Anomaly API (/api/v1/anomaly/*): Anomaly detection services
- Sensor API (/api/v1/sensors/*): IoT sensor management and control
- Data API (/api/v1/data/*): Data management and sample generation

### 5. FRONTEND ARCHITECTURE (React/TypeScript)

**Key Features:**
- Interactive dashboard with real-time data visualization
- Dedicated sensors page for IoT network monitoring
- Responsive design with modern UI/UX
- Real-time chart updates with Recharts library
- Intuitive sensor control interface with toggle switches
- Network health statistics and monitoring

**Core Pages:**
- Main Dashboard: Real-time equipment health monitoring

- Documentation Viewer: In-app documentation access
- Responsive design for desktop and mobile devices

## HOW THE SYSTEM WORKS

### DATA FLOW PROCESS

1. **IoT Sensor Network**: 16 industrial sensors continuously monitor equipment conditions, updating every 2 seconds
2. **Data Collection**: Real-time sensor data is collected and processed by the backend sensor manager
3. **Data Preprocessing**: Sensor readings are normalized and formatted into 24-feature vectors for ML models
4. **Model Inference**: Three AI models process the data simultaneously:
   - XGBoost predicts Remaining Useful Life
   - LightGBM classifies failure risk levels
   - Isolation Forest detects anomalies
5. **Explainability Layer**: SHAP and LIME provide interpretations of model decisions
6. **Frontend Visualization**: Results are displayed in real-time dashboards with interactive charts
7. **Alerting System**: Critical conditions trigger visual and analytical alerts

### REAL-TIME MONITORING

- Sensors update every 2 seconds for immediate response to equipment changes
- Dashboard refreshes every 15 seconds with latest predictions
- Sensor control page updates every 5 seconds for responsive interaction
- Health status indicators provide instant visual feedback (Normal, Warning, Critical)
- Network statistics show overall system health metrics

## INSTALLATION AND EXECUTION

### PREREQUISITES
- Python 3.8+
- Node.js 16+
- npm or yarn
- Git (recommended)

### UNIVERSAL SETUP METHOD (RECOMMENDED)
1. Run the universal setup manager:
   ```
   python setup_manager.py
   ```
2. Follow the on-screen menu options:
   - Option 1: Check System Requirements
   - Option 2: Complete Setup (Install Dependencies)
   - Option 3: Run Both Frontend & Backend

### MANUAL SETUP METHOD
**Backend Setup:**
```
cd Backend
python -m venv venv
source venv/bin/activate  # On Windows: .\venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

**Frontend Setup:**
```
cd FrontEnd
npm install
npm run dev
```

### ACCESSING THE APPLICATION
After starting both servers:
- Main Dashboard: http://localhost:8080/
- Sensors Page: http://localhost:8080/sensors
- Backend API: http://localhost:5000/

## SCALABILITY AND EXTENSIBILITY

### Adding New Sensors
1. Edit `Backend/AI/sensor_manager.py`
2. Add new sensor entries to the `factory_sensors` list
3. Define sensor properties (name, type, location, description)
4. Restart the backend server

### Customizing ML Models
1. Retrain models using notebooks in `models/notebooks/`
2. Add model loading functions in `Backend/AI/model_manager.py`
3. Create new API endpoints in appropriate files in `Backend/api/`
4. Update frontend components to display new model results

### System Scaling
- Horizontal scaling through multiple backend instances
- Frontend scaling via CDN or multiple servers
- Database integration for persistent data storage
- WebSocket support for faster real-time updates

## TROUBLESHOOTING AND SUPPORT

### Common Issues
- Port conflicts: Change ports in configuration files
- Dependency installation failures: Ensure virtual environment activation
- Connection issues: Verify both servers are running and CORS settings
- Sensor data not updating: Check backend sensor manager initialization

### Testing
- Backend API testing: `python test_api.py` in Backend directory
- IoT sensor testing: `python test_sensors.py` in root directory
- Manual API testing: Use browser or tools like Postman to access endpoints
